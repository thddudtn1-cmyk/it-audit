## 1. 개요

IT 자체감사의 계획·점검·발견사항·조치 이행을 엑셀과 한글 문서 대신 하나의 웹 시스템에서 관리한다.

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | IT 자체감사 관리 시스템 (가칭) |
| 한 줄 설명 | 자체감사 체크리스트 작성, 증적 첨부, 지적사항 조치 추적을 웹에서 처리하는 도구 |
| 성격 | 토이프로젝트 (개인 개발, 추후 사내 도입 검토용 프로토타입) |
| 버전 | v0.2 (현행 감사 문서 4종 분석 반영) |

## 2. 배경 및 문제 정의

현재 자체감사는 문서와 파일 취합 중심이라 감사 자체보다 페이퍼워크에 시간이 더 든다.

- 점검 체크리스트를 매년 엑셀로 복사해 쓰고, 버전이 담당자마다 갈라진다.
- 증적(캡처, 로그, 결재 문서)을 메일과 공유폴더로 받아 항목별로 다시 정리해야 한다.
- 지적사항의 조치 기한과 이행 여부를 별도 표로 수기 추적한다.
- 결과보고서 작성 시 같은 내용을 여러 문서에 옮겨 적는다.
- 전년도 감사 결과를 찾아보려면 폴더를 뒤져야 한다.

학습 측면에서는 실무 도메인(감사 업무 흐름, 권한, 증적 관리)을 직접 모델링해 보는 것도 목적에 포함한다.

## 3. 현행 감사 프로세스 분석

현행 IT 자체감사는 분기마다 엑셀 4종(체크리스트 → 점검 총괄표 → 적정성 점검(구 사전요청자료) → 개선사항 관리대장)을 거치며, 같은 점검항목이 문서마다 이름을 바꿔 최대 4번 옮겨 적힌다. 시스템은 이 4개 문서를 하나의 데이터 흐름으로 묶는다.

### 현행 문서 4종

| 문서 | 단위·주기 | 작성 → 사용 | 규모 (받은 파일 기준) | 시스템에서 |
| --- | --- | --- | --- | --- |
| ② IT자체감사 체크리스트 | 연간 계획, 연 1회 개정 | 주관자 작성 → 분기 총괄표의 원본 | 감사 영역 3개 · 감사 항목 22개 · 항목 상세 43개 | 체크리스트 마스터 (F-02) |
| ③ 분기 IT자체감사 총괄표 | 분기 | 주관자 배포 → 담당자별 점검 기입 | 2026년 3분기 14건 | 분기 점검 회차 (F-03\~F-05) |
| ④ 적정성 점검 (구 '적정성 점검 사전요청자료') | 분기, ③ 감사부서 제출 후 | 감사부서가 제출된 점검 내역을 항목별로 검토 → 필요 시 보완자료 요청 → 담당자 제출 | 2026년 2분기 4건 (기존 사전요청자료 양식) | 감사부서 적정성 점검 (F-06) |
| ⑤ IT자체감사 개선사항 관리대장 | 누적 (2024년 4Q 이후), 시트 2개: 개선사항·권고사항 | 분기 점검 제출 시 자동 등록 → 담당자 조치 | 양식만 제공 | 개선사항·권고사항 관리 (F-07) |

### 분기 점검 흐름

(흐름도: 1 체크리스트 개정[주관자] → 2 분기 회차 생성·배정[주관자] → 3 점검결과·증적 입력[담당자] → 4 총괄표 검토·제출[주관자] → 5 제출된 분기 점검 내역 검토[감사부서] → 6 보완자료 요청 시 자료·비고 제출[담당자] → 7 적정·미흡 확정 판정, 권고사항 등록[감사부서] / 4의 감사부서 제출 시점에 점검결과가 정상이 아닌 항목은 감사부서 검토와 관계없이 관리대장에 자동 등록(8)[시스템] → 9 조치 이행 예정→진행중→완료[담당자] → 10 조치 확인·종결, 미완료는 다음 분기 이월[주관자])

현재는 화살표마다 엑셀 파일이 메일로 오가고, 시스템에서는 같은 회차 데이터의 상태만 바뀐다.

### 분기별 점검 대상

분기 총괄표는 체크리스트에서 '감사 시기 = 해당 분기'인 항목과 '매분기' 항목 5개를 합쳐 만든다. 2026년 3분기는 3분기 항목 10개 중 9개 + 매분기 5개 = 14건이고, 빠진 1개는 ② #25 시스템 계정 접근(그룹 IT감사)이다.

| 분기 | 해당 분기 항목 | 매분기 항목 | 회차 대상 (제외 전) |
| --- | --- | --- | --- |
| 1분기 | 6 (#1\~6) | 5 | 11 |
| 2분기 | 13 (#8\~20) | 5 | 18 |
| 3분기 | 10 (#23\~32) | 5 | 15 → 실제 14 |
| 4분기 | 9 (#33, #35\~41, #43) | 5 | 14 |

매분기 항목: #7 운영시스템 적용 승인, #21 불필요 테이블, #22 저장 프로시저 정합성, #34 프로그램 변경 제3자 검증, #42 데이터변경 통제.

### 분석에서 확인한 사실 → 설계 반영

| 확인한 사실 | 근거 | 설계 반영 |
| --- | --- | --- |
| 감사 시기는 감사 항목이 아니라 항목 상세 단위로 정해진다 | ② '테스트 절차' #6은 1분기, #7은 매분기 | 마스터의 최소 단위 = 항목 상세 (영역 > 항목 > 상세 3단계) |
| 회차마다 빠지는 항목이 있다 | 3분기 총괄표에 #25(그룹 IT감사) 없음 | 회차 항목별 '제외 여부·제외 사유' |
| 감사부서는 제출된 점검 내역을 검토하고, 확인이 더 필요한 항목만 보완자료를 요청한다 | 2분기 18개 중 4개(#8, #10, #12, #17) 요청 | 점검 대상 항목 전체를 검토 대상으로 두고, 보완 요청·판정 시점에 적정성 점검 기록 생성 |
| 사전요청자료의 비고가 조치계획으로 이어진다 | ④ #4 비고 "26년 4분기 내 조치" | 개선사항의 개선 방안·개선예정일 기본값: 점검 제출 시 ③ 조치내용·개선 예정일 (감사부서 미흡 확정 등록 시에는 ④ 비고 우선) |
| 점검결과 등급이 문서마다 다르다 | ③ 범례 4단계, ③ 셀 메모 3단계, ⑤ 드롭다운 H5는 4단계·H6:H9는 3단계 | 정상·개선필요·미흡·위험 4단계로 통일 |
| 개선 1건이 감사 항목 여러 개에 걸친다 | ⑤ 개선 방안·조치 결과 셀이 3행 병합(J12:N14) | 개선사항 : 점검항목 = N:M |
| 표본 점검이 있다 | ③ "ICMS 시스템변경 랜덤 5개", "데이터변경 랜덤 3개" | 사전요청자료에 '표본 수' 필드 |
| 회신 없이 끝나는 항목이 있다 | ③ 색상 범례 "회신불필요" | 회차 항목별 '회신불필요' 표시 |
| 복사해 쓴 흔적이 남는다 | 3분기 파일의 시트명이 '2026\_2Q', 2026년 총괄표의 사전요청자료에 '2025 3Q' | 연도·분기는 회차에서 자동 표기 |
| 감사부서는 미흡 외에 권고사항도 남긴다 | ⑤ '권고사항' 시트 (점검 결과 없이 상세 내용만) | 개선사항과 같은 표에 '구분: 개선/권고' |

## 4. 목표 / 비목표

**목표**

1. 분기 점검 1회차의 회차 생성 → 담당자 점검 → 감사부서 적정성 점검 → 개선사항 조치 → 종결을 한 시스템 안에서 처리한다.
2. 체크리스트·총괄표·적정성 점검·관리대장 4종을 하나의 데이터로 잇고, 증적을 항목 단위로 붙여 메일·폴더 취합과 옮겨 적기를 없앤다.
3. 개선사항의 개선예정일과 조치 결과를 분기를 넘어 누적 추적하고 대시보드에서 한눈에 본다.

**비목표 (이번 버****전에서 안 하는 것)**

- 그룹웨어 결재, 인사 시스템, SSO 연동
- 감사 대상 시스템 로그의 자동 수집·분석
- 결과보고서의 기관 양식(한글 hwp) 완벽 재현 — 엑셀/PDF 출력까지만
- 모바일 전용 화면
- 다수 회사(멀티테넌트) 지원

## 5. 사용자 및 시나리오

사용자는 점검을 주관하는 쪽(주관자), 점검하는 쪽(각 팀 담당자), 점검의 적정성을 확인하는 쪽(감사부서) 세 부류에 관리자·조회자가 더해진다.

| 역할 | 누구 | 주요 행동 | 현행 문서에서 |
| --- | --- | --- | --- |
| 관리자 | 시스템 운영자 (본인) | 사용자·권한, 담당팀 코드 관리 | — |
| 자체감사 주관자 | IT 자체감사 담당 | 체크리스트 개정, 분기 회차 생성·담당 배정, 총괄표 검토·감사부서 제출(제출 시 관리대장 자동 등록), 관리대장 관리·종결 | ② 작성, ③ 배포·취합, ⑤ 관리 |
| 점검 담당자 | 각 IT 담당팀 담당자 | 배정 항목 점검결과·점검 내용 상세 입력, 적정성 점검 보완자료 제출, 조치 현황 입력 | ③ 기입, ④ 보완자료 제출, ⑤ 조치 |
| 감사부서 | 적정성 점검 수행자 | 제출된 점검 내역 검토, 보완자료 요청, 적정·미흡 확정 판정, 권고사항 등록, 조치 결과 확인 | ④ 작성 |
| 조회자 | 팀장·IT담당 임원 | 회차 진행 현황과 개선사항 조회 | — |

**핵심 시나리오**

1. 주관자는 분기 점검을 시작하기 위해 연도·분기를 고르고, 시스템이 체크리스트에서 '해당 분기 + 매분기' 항목을 뽑아 회차를 만든다. 주관자는 제외 항목을 빼고 담당팀·담당자·사전요청자료를 지정한다.
2. 점검 담당자는 자기 항목을 점검하기 위해 로그인해 배정 항목의 점검결과(정상/개선필요/미흡/위험)·점검 내용 상세를 입력하고 증적을 올린 뒤 제출한다. 정상이 아니면 조치내용과 개선 예정일도 적는다.
3. 주관자는 총괄표를 확정하기 위해 제출된 항목을 검토·반려하고, 전체가 모이면 감사부서에 제출한다(회차 잠금).
4. 감사부서는 적정성을 확인하기 위해 제출된 분기 점검 내역(점검결과·내용·증적)을 항목별로 검토하고, 더 확인이 필요하면 보완자료를 요청한다. 담당자는 보완자료와 비고를 제출하고, 감사부서는 다시 검토한다.
5. 감사부서는 검토 결과 미흡사항을 확정하고(필요하면 권고사항도 등록) 적정성 점검을 마친다. 개선사항 관리대장은 감사부서 검토를 기다리지 않는다: 주관자가 분기 점검을 감사부서에 제출하는 시점에 점검결과가 정상이 아닌 항목(개선필요·미흡·위험)이 개선사항으로 자동 확정 등록되고, 감사부서 미흡 확정은 정상으로 제출된 항목에 대해서만 주관자가 추가 등록한다.
6. 점검 담당자는 개선사항을 해소하기 위해 개선 방안·개선예정일을 입력하고, 조치 결과(예정 → 진행중 → 완료)와 증빙자료를 갱신한다. 조치 결과가 '완료'가 되면 주관자가 검토해 **최종확정**(= 종결)하거나 사유를 적어 이전 단계(진행중·예정)로 되돌린다. 검토를 기다리는 동안 담당자는 수정할 수 없고, 되돌려지면 반려 사유를 보고 다시 조치한다. 최종확정하지 않은 건은 다음 분기로 이어진다.

## 7. MVP 범위

MVP 완성 기준은 "분기 점검 1회차를 생성해 감사부서 확인과 개선사항 등록까지 시스템 안에서 끝낼 수 있다"이다.

- [ ] F-01 로그인·권한 (5개 역할)
- [ ] F-02 체크리스트 마스터 (② 엑셀 43개 항목 일괄 업로드)
- [ ] F-03 분기 회차 생성·담당 배정
- [ ] F-04 담당자 점검 입력·증적 업로드
- [ ] F-05 총괄표 검토·감사부서 제출
- [ ] F-06 적정성 점검: 점검 내역 검토·보완자료 요청·제출·미흡 확정
- [ ] F-07 개선사항·권고사항 등록과 조치 결과 갱신
- [ ] F-08 대시보드 (회차 진척률, 개선예정일 경과 목록 수준)

## 8. 비기능 요구사항

토이프로젝트지만 사내 도입을 염두에 두므로 보안·감사추적은 처음부터 고려한다.

| 구분 | 요구사항 |
| --- | --- |
| 보안 | 비밀번호 해시 저장(BCrypt), 세션 타임아웃 30분, 역할 기반 접근 통제 |
| 파일 | 첨부 1건 50MB 이하, 허용 확장자 제한(pdf, xlsx, docx, png, jpg, zip, txt) |
| 감사추적 | 판정·종결·파일 삭제는 이력을 남기고 물리 삭제하지 않음 |
| 환경 | 폐쇄망 설치를 가정해 외부 CDN·외부 API 의존 없이 동작 |
| 브라우저 | Chrome, Edge 최신 버전 (데스크톱) |
| 성능 | 사용자 20명 이하, 목록 화면 응답 2초 이내 |
| 백업 | H2 BACKUP TO 일 1회 + 첨부 디렉터리 복사, 앱은 정상 종료 절차로 내림 |

**주요 엔티티**

| 엔티티 | 주요 컨럼 | 관계 | 현행 문서 |
| --- | --- | --- | --- |
| User | 아이디, 이름, 담당팀, 역할 |  | — |
| ChecklistItem (체크리스트 마스터) | 순번, 감사 영역, 감사 항목, 항목 상세, 감사 시기, 법규/규정, 적용연도, 사용여부 |  | ② 1행 = 1건 |
| AuditRound (분기 점검 회차) | 연도, 분기, 상태(작성중·검토중·감사부서 제출·완료) | 1:N RoundItem | ③ 파일 1개 |
| RoundItem (회차별 점검항목) | 담당팀, 담당자, 사전요청자료, 표본 수, 점검결과, 점검 내용 상세, 비고1, 조치내용, 개선 예정일, 회신불필요, 제외 사유, 제출 상태 | N:1 AuditRound, N:1 ChecklistItem | ③ 1행 = 1건 |
| AuditRequest (적정성 점검 기록) | 보완 요청자료(요청 시), 비고, 요청일, 제출일, 상태(보완 요청·보완 제출·검토완료), 미흡 확정 여부·확정 점검결과·미흡 내용 | N:1 RoundItem (감사부서가 처음 검토·요청할 때 생성) | ④ 1행 = 1건 |
| Improvement (개선사항·권고사항) | 구분(개선/권고), 점검 결과, 점검 내용 상세(권고: 상세 내용), 개선 방안, 개선예정일, 조치 결과, 조치 현황, 종결일 | N:M RoundItem (ImprovementItem) | ⑤ 두 시트 |
| Evidence (증적·증빙자료) | 파일명, 경로, 크기, 업로더, 삭제여부 | N:1 RoundItem · AuditRequest · Improvement 중 하나 | 메일·공유폴더 |
| ActivityLog | 사용자, 행위, 대상, 일시 |  | — |

코드값은 세 가지다. 점검결과 = 정상(법규/규정 준수) · 개선필요(정상이나 일부 개선 필요, 긴급 아님) · 미흡(위반은 아니나 개선 필요) · 위험(법규/규정 위반). 조치 결과 = 예정 · 진행중 · 완료. 감사 시기 = 1분기 · 2분기 · 3분기 · 4분기 · 매분기.

③의 '조치내용 및 개선 예정일'은 글과 날짜가 한 칸에 섞여 있어, 시스템에서는 조치내용(텍스트)과 개선 예정일(날짜) 두 필드로 나눈다. ⑤의 '담당부서/담당자'도 담당팀·담당자로 나눠 저장하고 화면에서만 합쳐 보여준다.
